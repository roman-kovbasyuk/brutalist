# Changelog

Before 1.0, patch versions add capabilities and minor versions contain breaking changes (Automation Studio decision D25). Breaking changes record the owner's approval.

## 0.1.5 — 28 September 2026

Brings the Automation Studio pilot additions into this repository, which is again the single source. All changes are additive; this repository's 0.1.4 redesigns win where both copies changed the same component.

- **Pages.** A new documentation section, `pages.html`, with complete example products built only from public exports, one page per product listing every screen: Admin (app shell, dashboard, data table, record detail, settings, menus and four authentication screens), a product landing page (one screen per section) and a consumer phone app. Screens preview live at desktop, tablet and phone widths in an iframe, and open full screen under a bar that leads back to the catalog. Old single-page links resolve to their product and screen.
- **`NavigationList` submenus:** items take `children`; a chevron opens the submenu, and the branch holding the current page opens by itself. `expandedIds` and `onExpandedChange` control it. Page code lives in `src/atomic/screens/pages` and is not part of the published library.
- **Data visualisation components:** `StatCard`, `Sparkline`, `LineChart`, `BarChart` (grouped or stacked), `DonutChart` and `BarList`, plus `formatCompact`. Series take a fixed, colour-vision-checked palette in order (`--a-color-chart-1` … `-6`); charts measure their container, have a table view, and are keyboard readable with arrow keys.
- **`TabBar`:** bottom navigation for phone apps.
- **Dashboard widgets:** `Tile` (a widget container whose `tone` — surface, canvas, ink, accent, yellow, green, violet or orange — re-points the colour tokens so everything inside stays readable) and `Figure` (a display-size number with caption and change). New charts: `Gauge` (half-circle part-to-whole), `ProportionBar` (one split bar with shares) and `Heatmap` (two categories on a validated one-hue blue ramp, keyboard readable; `density="compact"` draws small square cells for twelve or more columns and shortens column labels to initials when narrow). `BarChart` gains `appearance="pill"` with `highlight` and `showValues`; `DonutChart` gains `appearance="ring"` and `legendPosition`.
- **UI blocks:** `AppShell` (sticky sidebar that becomes a menu drawer at 960px and below) and `PageHeader`.
- **Dark theme (preview):** `AtomsRoot` accepts `theme="light" | "dark"`; nested roots, including overlay portals, inherit it (`useTheme`). Light remains the default and the primary, reviewed theme. New token `--a-color-on-accent` for text on accent, success and warning fills.
- Additive props: `TextField` `hideLabel`; `Popover` `icon` and `iconOnly`; `Dialog`/`Drawer` `triggerIcon` and `triggerIconOnly`.
- Automated accessibility checks (axe) run against every example page in both themes.
- Gaps found while building the pages, fixed in the library: `Rating` gains a compact read-only display (`readOnly compact`: small stars announced as one image); `DigitInput` advances as you type, goes back on Backspace, fills from a pasted code, accepts `onComplete` and `autoComplete` (default `one-time-code`), links its error to every box and shrinks its boxes to 40px so six fit a phone; `Button` gains `fullWidth`; `Divider` gains `label` for “or” separators; `AppShell` gains `contentElement` and `PageHeader` gains `headingLevel` for embedding.
- Added `NotificationList`: a short feed for a popover or panel with a leading avatar or icon, the message, detail and time, bold unread rows with a dot, an unread count and “Mark all read”; rows with `href` are links that lift on hover. The admin shell and the phone example use it.
- `Button` gains `shape="circle"` (same sizes, fully round); `Menu` and `Popover` icon triggers pass it through. Used for tile corner actions on the dashboard and the icon buttons of the phone example.
- `RadioGroup` gains `layout="scroll"` (tags variant: one row that scrolls sideways, aligned to the content edge) and `hideLabel`; `Select` and `Checkbox` gain `hideLabel` (a hidden label no longer takes space, so a row checkbox centres in its table cell). The phone example uses both: categories as one swipeable row and a single-row Filters/Sort toolbar.
- `Tabs` and `SegmentedControl` align with the content edge: the scroller keeps 8px of room for the focus ring and lift but cancels it with a negative side margin.
- Fixes: `TabMenuVertical` buttons use the design-system font and a 44px row, and the current row is visible on canvas; `Avatar` puts its status in its accessible name instead of an invalid label, and `size="large"` uses an existing token; `CommandMenu` closes on Escape; `TabBar` counts are read after the label (“Inbox, 3 new”).
- Dark theme uses the Automation Studio palette inside this repository's inheritance model (themes and custom properties still flow into portals); `Theme`, `darkColor`, `themeVariables` and `useTheme` are exported from Basics. Text on accent, success and other fills uses `--a-color-on-accent` in alerts, badges, steppers and workflow steps.
- `NavigationList` keeps this repository's submenu (`children` through `Disclosure`) and now opens the branch holding the current page by itself.

- **Website blocks:** `SiteHeader`, `ReleaseNotice`, `SiteFooter`, `IntroSection`, `CapabilityGrid`, `ActionSection`, `ImpactSummary`, `ProcessSteps`, `PlanComparison`, `SubscriptionSection` and `QuestionsSection`, each responsive to its own container, in both themes, with two documented examples and usage guidance.
- `Button` accepts `href` and renders a link with the same look, for destinations such as a checkout. `Dialog` and `Drawer` accept `closeLabel`.
- **AI manifest:** the package ships `ai/manifest.json` and `ai/llms.txt`, generated from the component list, usage guide and examples: purpose, when to use something else, props and example source for every component and block, plus the page templates. `npm run build:ai-manifest` regenerates them.
- `templateManifest` lists every page screen with its tasks, files and the public exports it uses.
- Usage guidance now covers every component and block.

## 0.1.4 — 25 September 2026

UI blocks redesign, documentation navigation and duplicate cleanup. All changes are additive; nothing is removed.

- **Blocks.** Account panels (sign-in, registration, recovery, verification) gain an optional `description`, keep the recovery link beside the password, separate provider sign-in under an “or” rule and move secondary routes into a ruled footer. Settings blocks (`PreferencesPanel`, `AccessPanel`, `ProfileSettings`) render as split panels with label-and-controls rows that stack in narrow containers, and a closing action bar; `PreferencesPanel` and `AccessPanel` gain `description`. `MemberDirectory` shows compact rows with a role tag and an icon menu instead of a label/value list. `ProfileSummary`, `WorkspaceHeader`, `BreadcrumbHeader`, `WorkspaceSwitcher`, `AccountMenu`, `PrimaryNavigation`, `SidebarPanel` and `CommandSearch` get consistent headers, identity triggers and rails. `CommandSearch` draws a search-field trigger with its shortcut. `PromptInput` gains an optional `selector` (a single-choice dropdown beside the attach button, such as a response style) and exports `PromptSelector`.
- **Components.** `Avatar` gains `shape="square"` for organizations and brand marks, its `large` size renders again (it referenced an undefined token), and initials scale with size (12px small, 14px medium, 18px large). `PasswordField` moves its visibility toggle into the field. `DigitInput` keeps every slot on one row. `Checkbox` and `TextField` gain `hideLabel`; `Table` selection uses it so row labels are no longer printed. `Disclosure` gains `variant="quiet"`. `NavigationMenu` items gain `current`. `PasswordStrength` shows a checklist with icons. Selected choice cards stay white and show selection through the filled control, a doubled ink edge and a small offset shadow; checkbox and radio cards put the control in its own column, centred on the label and description, which now share one text column. `InlineConfirmation` turns its trigger into a same-height confirmation strip in place, focuses Cancel, keeps failures beside the question for retry, and gains `confirmLabel` (defaults to `label`), `cancelLabel`, `tone` and `icon`. `DatePicker` and `DateRangePicker` use one bordered date field with the design-system calendar as the only picker (the browser's selector is hidden), a clear action and, for single dates, a Today shortcut; `DatePicker` gains `clearable`. The range picker shows start → end in one field under a single group label. `ColorPicker` moves to its own module and becomes a standard field: a swatch that opens the system picker, a hex input that accepts shorthand and explains invalid values, and preset swatches with a check. `FileList` rows show size and status in one line, a thin progress track and icon-only actions with the same accessible names; `AttachmentArea` fills its container and gains a `tools` slot beside the attach button. Menu radio and checkbox items keep an indicator column so checked and unchecked labels align. `Fieldset` places its legend inside the box on the content edge. `TimeField` shares the date field and opens a list of permitted times at its step (30 minutes when unset) in place of the browser's clock picker. `TagInput`'s entry sits right after the last tag at tag size and widens as you type, instead of filling the row. `Toggle` and `Checkbox` hints and errors start at the label text. `WorkflowSteps` draws a full-width track (solid behind completed steps, dashed ahead) with labels under the circles, inherits the page font and no longer fades upcoming steps; `VerticalStepper` uses the same state colors. `Stat` becomes a tile with the period beside the label, a tabular value, an arrowed comparison and a dash plus note when no value exists. `Table` gains `variant="simple"` and `striped`. `Alert` titles are one step larger. `Avatar` gains `tone` (`auto` gives each name a stable color), shows presence as a ringed dot above the image and includes it in the accessible name; `AvatarGroup` gains `tone` and stacks earlier avatars on top so every dot stays visible. `Spinner` draws a block that eases around a 2×2 grid of slots instead of a rotating icon. `CodeExample` moves Copy from the panel header to the code view beside the filename. `NavigationList` row actions are compact so rows stay 36px, and a current row with an action is outlined as a whole. `WorkflowSteps` draws a full-width track (solid behind completed steps, dashed ahead) with labels under the circles, inherits the page font and no longer fades upcoming steps; `VerticalStepper` uses the same state colors. `Stat` becomes a tile with the period beside the label, a tabular value, an arrowed comparison and a dash plus note when no value exists. `Table` gains `variant="simple"` and `striped`. `Alert` titles are one step larger. `Avatar` gains `tone` (`auto` gives each name a stable color), shows presence as a ringed dot above the image and includes it in the accessible name; `AvatarGroup` gains `tone` and stacks earlier avatars on top so every dot stays visible. `Spinner` draws a block that steps around a 2×2 grid instead of a rotating icon. `CodeExample` moves Copy from the panel header to the code view beside the filename. `CommandMenu` replaces its instruction sentence with a key legend and uses `Kbd`. `SectionHeading` spaces its actions and leaves 24px above them when they wrap under the title; the breadcrumb and workspace headers gain more space between breadcrumb, title and closing rule. `Menu` items highlight with the canvas tone and show a 1px inset ink edge on focus, replacing the cyan fill and clipped outline; closing a menu with the pointer returns focus to its trigger without the keyboard ring, and a menu is at least as wide as its trigger. Undefined tokens in the timeline, navigation menu shadow and settings styles are fixed.
- **Deprecated, still exported:** `CompactButton` (use `Button size="compact"`), `AvatarGroupCompact` (use `AvatarGroup size="small"`), `Notification` (use `Banner`), `StatusBadge` (use `Tag status`), `TabMenuVertical` (use `Tabs orientation="vertical"`). Their documentation pages redirect to the canonical component. Removal needs the owner's approval and a minor release.
- **Documentation.** One shared shell replaces three copies. The header links the four areas—Start, Basics, Components, Blocks—and the sidebar lists only the current area. Components are grouped by responsibility with labels that match page titles; blocks are grouped by task. A ⌘K or `/` page finder searches every area, including familiar alternative names. Every block page, and component pages without hand-written variants, shows distinct registered examples whose code comes from the same module as the preview, and the copied import line sits under the title. Helper sentences, eyebrows and the repeated footer are gone; the version badge reads the package version.

## 0.1.3 — 24 September 2026

- `Alert` accepts `children` as body content shown inside the alert below the description, for a short list, a link or a small form. `title` is now optional, and no empty heading is rendered without one. Existing uses are unchanged.

## 0.1.2 — 17 September 2026

- Added `TagInput`: free-text tags added with Enter, styled as a dashed, tag-shaped entry control inline with the existing tags that grows into the rest of its row, so its placeholder can carry a full sentence (closes gap R7). Typed text is trimmed, deduplicated case-insensitively and length-limited; Backspace on an empty entry removes the last tag; blur commits a pending entry.
- Removable `Tag`s and `RadioGroup` tags-variant choices now lift on hover and focus, matching `Button` and `Panel`. Plain, non-removable tags are unaffected — they are not interactive.

## 0.1.1 — 17 September 2026

- `RadioGroup` gains `variant: 'default' | 'tags'`. The tags variant draws the options as wrapping, tag-shaped choices that remain native radios; its custom answer field appears only while the custom option is selected.
- `RangeSlider` handles share one scale: both span the full range and are clamped so they never cross. Previously each handle's range stopped at the other, so the handles were drawn on different scales and the upper handle locked when both sat at the maximum.
